# Multi-repository coordination core engine Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the switched-off Maku core that plans, authorizes, files, orders, integrates, and completes one coherent change across exactly two public repositories, without giving the parent any execution or merge authority.

**Architecture:** A typed `CoordinationPlan` and deterministic canonical/materiality library sit below a distinct `coordination_plan` broker tool that consumes the conversational intake plan's existing governed route. A coordination service on the factory API stores full plan versions and separate parent/child confirmations on an additive Task contract; the existing Task reconciler gains a coordination-only parent path, ordinary repository-local children, landed-artifact admission, a read-only primary-repository `triager` integration path, and one final arm hold. Fixed lifetime allocations compose with the existing atomic daily ledger. The parent completes only after final integration, and every failure yields one deterministic proposed action, never a rollback playbook.

**Tech Stack:** Go 1.25, controller-runtime + envtest + CEL, Kubernetes CRDs generated by `task crd:gen`, controller-runtime fakes, `httptest`, OpenTelemetry, MCP over `POST /mcp`, `internal/httpx`, SHA-256 canonical JSON, GitHub REST/GraphQL through `internal/factory/forge`, `task`; ai-native-ref kustomize/Flux and Python/render gates.

**Spec:** [the corrected multi-repository design](../specs/2026-11-05-v4-multi-repo-coordination-design.md), especially MR1–MR12 and MR16–MR17, the Plan/Task/Issues/Dependencies/Integration/Budget/Admission/Materiality/Recovery/Security/Rollout contracts and O1–O10/O12/O14/O15. The governed planner seam is [the conversational design](../specs/2026-11-05-v3x-conversational-devex-design.md#seams), CD17–CD18 and “To the multi-repository design”. The reusable implementation seam is [the conversational intake plan](2026-11-05-v3x-conversational-intake-maku-plan.md#seam-coordination): land its Maku PRs 1–2 before this plan's PR 3, then consume `internal/intake.Model`, `Guard`, the effective-requester resolution and the same daily limiter. `plan/v1` remains unchanged and single-repository.

Commits and PRs are conventional English with no trailers or attribution.
- **One logical switch.** `coordination: {mode: off|plan|execute, publicOnly: true, maxChildren: 2}` defaults to `off`, `true`, and `2` in both strict Maku config decoders. Any other `maxChildren`, and `publicOnly: false` in this release, is invalid. ai-native-ref projects the same value into factory and broker config; there is no independent Slack enable flag. `off` lists no coordination tool and serves no coordination API; `plan` permits drafts/confirmations only; `execute` alone may file issues or create runs.
- **Activation is a capability gate, not a version check.** Every execute-time draft filing, child admission/resume, and integration admission calls `ExecutionPrerequisites.Ready(ctx, repository)`. It must prove both v4 item 3 repository-declared class authority and v4 item 4 hardened safe outputs/threat checks for every child and integration input. The stage-1 `mergepolicy.Watch` parser/observer is never evidence. Missing or regressed capabilities return `coordination_prerequisites` and start nothing; `plan` remains available. Existing single-repository Tasks are unchanged.
- **Public and bounded.** Execute requires exactly two children on two distinct configured public repositories; planning may hold an incomplete editable draft but rejects a third child, duplicate repository/child/artifact ID, unknown field, dependency cycle, non-file artifact, or artifact over 64 KiB. `primary.repository` is one child repository. Private/mixed families return `private_repository_unsupported` before a model call and again before filing/admission.
- **No new authority.** No new CRD, AgentRun role, gateway audience, STS trust policy, parent branch, parent PR, parent repository-token-bearing run, parent merge call, automatic cross-repository rollback, fleet campaign, arbitrary DAG/fan-out, cross-factory handoff, private integrated family, or third repository. Integration uses the existing primary `octo-sts/<primary>/<triager>` path. No plan task may edit gateway policy/listener files.
- **Splitter discrimination.** `spec.kind: coordination|integration`, `source.kind: coordination`, `spec.coordinationParent`, `PhaseCoordinating`, `agents.ogenki.io/coordination-parent`, `factory/coordination`, and `factory/coordination-child` are the only new lineage vocabulary. Never reuse `Split`, `spec.parent`, `spec.split`, `status.split`, `agents.ogenki.io/parent`, `factory/child-of`, or splitter `TaskFacts.split/parent` for coordination.
- **Repository-local children.** A child is otherwise an ordinary issue Task with a frozen ready `TaskScope`, resolved class/template/tier/budget, no C7/scoper/split, its own issue/room/branch/token/PR/gate, and `source.requestedBy` equal to its child authorizer. Task, Room, issue, and every run repository must agree or admission refuses `cross_repository_lineage`. Parent confirmation never substitutes for a child's linked maintainer with current GitHub `write`.
- **Fixed budgets.** `planningMicroUSD + Σ child.budgetMicroUSD + integration.maxRuns*integration.runMicroUSD ≤ budget.totalMicroUSD`, with checked arithmetic. Child/integration allocations are immutable per generation and non-overlapping; independent siblings cannot spend one another's allocation. Every run still takes `reserveFactoryDay`'s atomic person-plus-fleet reservation. An affected replacement generation starts only after the old generation is stopped and its outstanding reservation is accounted.
- **Exact evidence.** Dependencies consume only `file` references at the producer's landed merge commit with repository/path, 40-hex merge and blob SHAs, 64-hex content SHA-256, and size. Integration manifests bind exact child head/merge SHAs and plan hash. A PR head, newer default-branch content, prose handoff, green child, or timestamp satisfies neither dependency nor completion.
- **Experience exclusions.** This plan implements no parent roles rail/UI/inbox/resume/notification rendering, privacy-filtered parent projection, Slack proposal mechanics, parent multi-worktree checkout, or parent summary fold. It declares the neutral contracts those consumers use below, but the unfiltered `CoordinationView` is internal only and is not exposed on a human route. The follow-on experience plan owns per-viewer/per-channel filtering and all rendering.
- **Owner gate.** The ai-native-ref change only pins and declares `mode: off`. No live repository issue, branch, run, merge, cluster mutation, or `plan`/`execute` switch-on occurs without a separate explicit owner go naming the cluster, two public proof repositories, maintainers, and time-bounded proof window. The core proof uses the MCP planner and factory confirmation API, not the excluded Slack/UI experience.

## Review Focus

1. **A crash after one issue write but before its parent status write.** Visible linked issues must remain `filing_incomplete`, replay must adopt rather than duplicate them, and no child Task may start until every parent/child marker exists. Owning test: PR 4, Task 8 (`TestFilingCrashReplayAdoptsWithoutStarting`).
2. **A repository check fails only on a later resume.** A stale cached fence/write/class success must not admit the child: loss of App access, fence ownership, maintainer membership, write permission, or resolved class pauses only that child and its dependents with `access_unverified`, `repository_not_owned`, `repository_permission`, or `policy_changed`. Owning test: PR 4, Task 9 (`TestAdmissionAndResumeRecheckRepositoryAuthority`).
3. **A producer artifact exists at a PR head or newer default branch but differs at the landed merge SHA.** It must not unlock the dependent; wrong type/size/digest records no landed reference and proposes exactly `retry_producer` for an unchanged plan. Owning tests: PR 5, Task 10 (`TestOnlyExactLandedArtifactUnlocks`) and PR 7, Task 15 (`TestArtifactFailureHasOneRecovery`).
4. **An integration-approved head moves, including while a live class can arm automatically.** The release is stale immediately, `DecideArm`'s final arm is replaced by `wait/integration_pending`, and no merger call occurs until a new manifest passes for the new head; the maintainer-approved path is identical. Owning test: PR 6, Task 13 (`TestIntegrationHoldCoversEveryArmAndStaleHead`).
5. **A material edit races an unaffected sibling and an affected generation with an outstanding reservation.** Unaffected work continues under its preserved fingerprint, affected future scheduling/releases stop, and replacement starts only after terminal old generation plus settled/released reservation accounting; static allocations never exceed the confirmed family total. Owning test: PR 7, Task 14 (`TestMaterialEditSerializesOnlyAffectedGenerations`).

## Experience-neutral contracts (declared here, rendered elsewhere)

These are versioned data contracts, not new HTTP surfaces. JSON field names are lower camel case; hashes are lowercase hex without a `sha256:` prefix. The follow-on experience plan must import these Go types or generate its wire types from them, not fork the fields.

```go

    Plan     v1alpha1.CoordinationPlan `json:"plan"`
    PlanHash string                    `json:"planHash"`
    Parent   *ParentConfirmation       `json:"parent,omitempty"`
    Child    *ChildAuthorization       `json:"child,omitempty"`
    Planning PlanningReconciliation    `json:"planning"`
}

type PlanningReconciliation struct {
    AttemptID          string `json:"attemptID"`
    EffectiveRequester string `json:"effectiveRequester"`
    ReservationID      string `json:"reservationID,omitempty"`
    SettlementID       string `json:"settlementID,omitempty"`
    ReservedMicroUSD   int64  `json:"reservedMicroUSD"`
    SettledMicroUSD    int64  `json:"settledMicroUSD"`
}

type CoordinationView struct {

    Phase                   string                         `json:"phase"`

    Budget                  CoordinationBudgetView         `json:"budget"`
    Recovery                *v1alpha1.RecoveryProposal     `json:"recovery,omitempty"`

}

type CoordinationChildView struct {
    ID                      string                        `json:"id"`
    Repository              string                        `json:"repository"`
    Task                    string                        `json:"task"`

    PlanningMicroUSD             int64 `json:"planningMicroUSD"`
    PlanningReservedMicroUSD     int64 `json:"planningReservedMicroUSD"`
    PlanningSettledMicroUSD      int64 `json:"planningSettledMicroUSD"`
    TotalMicroUSD                int64 `json:"totalMicroUSD"`
    AllocatedMicroUSD            int64 `json:"allocatedMicroUSD"`
    ChildrenReservedMicroUSD     int64 `json:"childrenReservedMicroUSD"`
    ChildrenSettledMicroUSD      int64 `json:"childrenSettledMicroUSD"`
    IntegrationReservedMicroUSD  int64 `json:"integrationReservedMicroUSD"`
    IntegrationSettledMicroUSD   int64 `json:"integrationSettledMicroUSD"`
    IntegrationMaxRuns           int   `json:"integrationMaxRuns"`
    IntegrationRuns              int   `json:"integrationRuns"`
}

type CoordinationIncident = v1alpha1.CoordinationIncident // {childID, reason, mergeCommitSHA, at time.Time}; never reopens Done

type CheckoutManifest struct { // contract only: no checkout implementation in this plan
    ParentTask  string           `json:"parentTask"`
    PlanVersion int32            `json:"planVersion"`
    PlanHash    string           `json:"planHash"`
    Children    []CheckoutChild  `json:"children"`
}

type CheckoutChild struct {
    ID             string                      `json:"id"`
    Repository     string                      `json:"repository"`
    Worktree       string                      `json:"worktree"`
    Room           string                      `json:"room"`
    Issue          string                      `json:"issue"`
    PR             string                      `json:"pr"`
    DependsOn      []string                    `json:"dependsOn"`
    Artifacts      []v1alpha1.LandedArtifact   `json:"artifacts"`
    HeadSHA        string                      `json:"headSHA,omitempty"`
    MergeCommitSHA string                      `json:"mergeCommitSHA,omitempty"`

```

`ParentConfirmation` is the CRD record `{planHash, actor, linkedGitHubLogin, confirmedAt}`. `ChildAuthorization` is `{childID, childFingerprint, planVersion, actor, repository, permission, fenceSHA, confirmedAt}`. In a child view, `DependsOn` contains child IDs and `Consumes` contains `<from>/<artifact>` IDs. `Issue` and `PR` in `CheckoutChild` are validated URLs, not numbers. A view consumer must filter every child by the viewer's GitHub read before exposure; this plan deliberately provides no unfiltered human endpoint.
