# The v4 landscape: what the Agent Factory lacks, against hosted agents, open-source platforms, governance practice and adopter demand

**Date:** 2026-10-31 · **Status:** research; the owner's selection is recorded in its last section and decided in the [v4 roadmap](2026-10-31-v4-roadmap-design.md) · **Follows:** the [v3 landscape research](2026-10-21-v3-landscape-research.md), the [automerge criteria research](2026-10-29-automerge-criteria-research.md) and the [harness roles research](2026-10-30-harness-roles-research.md)

## Close the gaps around the agent

The Agent Factory's missing features sit around the agent, not in it. Ranked by measured adopter demand first, then by how many of four lenses show the gap (hosted coding agents, open-source platforms, governance and evaluation practice, adopter demand), then by whether any effect was measured rather than announced, the eight strongest candidates for v4 are **pre-PR verification on real services, a review inbox with routing, fleet campaigns across repositories, the PR continuation loop, event triggers and schedules, outcome analytics per class and model, injection red-team drills, and hardening beyond validated outputs**. The demand is unusually explicit: Spotify says "code generation is no longer the bottleneck. PR review is" ([InfoQ](https://infoq.com/news/2026/03/spotify-honk-rewrite)), agentic PRs wait **17.6 h for pickup against 3.4 h** for unassisted ones across 8.1M PRs ([LinearB](https://linearb.io/library/ai-in-software-development)), and **each failed CI check cuts an agent PR's merge odds by about 15%** on public GitHub ([AIDev](https://www.alphaxiv.org/overview/2601.15195)). Product convergence is broad, but outcome data is thin: nearly every effect size is vendor-reported, the only controlled number is GitHub's memory result (**90% against 83% merge rate**), and no adopter publishes a revert rate or a cost per merged PR, both of which the factory already records. The factory still leads where nobody followed it: no hosted or open-source product reviewed documents merging on its own under a class policy with shadow decisions, caps and a breaker. That lead matters more now, because hosted vendors run on customers' machines and "runs in your cluster" no longer sets the factory apart. Six maintenance findings need fixing but are not features. The owner chose the initial v4 scope on 2026-10-31; the final section records that decision apart from the research and points each item at its evidence.

## 1. The field moved to the PR lifecycle; the factory still leads on merge policy

Hosted vendors spent 2026 on what happens after the agent writes code. GitHub renamed its agent **Copilot cloud agent** on 2026-04-01 and let it return a plan for approval before coding ([GitHub](https://github.blog/changelog/2026-04-01-research-plan-and-code-with-copilot-cloud-agent/)); on 2026-10-28 it shipped **Agent Merge**, which watches a PR and fixes failed workflows and conflicts but does not merge: "combined with auto-merge, GitHub merges the PR once all requirements are met" ([GitHub](https://github.blog/changelog/2026-10-28-agent-merge-watches-and-fixes-pull-requests-in-the-cloud/)). Cursor's cloud agents "automatically subscribe to PRs they create, then fix CI and address bot comments", and wake on Slack threads and schedules ([Cursor, 2026-08-19](https://cursor.com/changelog/08-19-26)). Devin's 2026 release notes are dominated by automations (schedules, PagerDuty and Slack triggers, a preflight script that can skip a run), review, and an on-call product that reached GA on 2026-10-19 ([Devin](https://docs.devin.ai/release-notes/2026)). Claude Code's cloud sessions added auto-fix PRs and scheduled tasks fired by cron, API or GitHub events ([Claude Code](https://code.claude.com/docs/en/claude-code-on-the-web); [scheduled tasks](https://code.claude.com/docs/en/routines)). The category also consolidated: Google's changelog says Jules "will wind down on December 31, 2026" in favour of Antigravity ([Jules](https://jules.google/docs/changelog/)), and OpenAI's docs now label Codex's cloud environments "Legacy" ([OpenAI](https://learn.chatgpt.com/docs/environments/cloud-environment)). The volume behind this is large: by September 2026 more than 40% of pull requests on GitHub began as an agent draft, up from 17% in March [S] ([TNW on Octoverse 2026](https://thenextweb.com/news/github-universe-copilot-fusion-octoverse-agents)).

Open source split into two poles, and both reached 1.0 in the last week of October. **GitHub Agentic Workflows (gh-aw) v1.0.0** (2026-10-26) is now the broadest open reference for triggers, agents that hold no write permission and request actions as typed "safe outputs", git-backed memory, outcome tracking and an external admission gate ([gh-aw](https://github.com/github/gh-aw/releases/tag/v1.0.0)). The Kubernetes runtime stack converged in the same week: agent-sandbox v1.0.9 (2026-10-29), Agent Substrate v1.0.0-rc.1 (2026-10-29) and kagent v1.0.0-rc1 (2026-10-30) ([agent-sandbox](https://github.com/kubernetes-sigs/agent-sandbox/releases/tag/v1.0.9); [Substrate](https://github.com/agent-substrate/substrate/releases/tag/v1.0.0-rc.1); [kagent](https://github.com/kagent-dev/kagent/releases/tag/v1.0.0-rc1)). OpenHands added scheduled and event automations, but RBAC, budgets and GitHub event triggers sit in its commercial Enterprise edition ([OpenHands](https://docs.openhands.dev/enterprise/enterprise-vs-oss.md)). Around them the field thinned: Daytona moved its core to a private codebase in June, Continue went read-only, and Roo Code archived ([Daytona](https://github.com/daytonaio/daytona); [Continue](https://github.com/continuedev/continue); [Roo Code](https://github.com/RooCodeInc/Roo-Code)). Inference: the factory's chosen layers, agent-sandbox and the OpenHands agent-server, sit on the active side of that split.

Against this field the factory's distinctive parts are still distinctive. **No product reviewed documents merging on its own under a class policy** with shadow decisions, daily caps and a regression breaker: GitHub delegates to its native auto-merge, and Devin Review gives authorised humans a merge button that can "bypass merge rules" ([Devin](https://docs.devin.ai/release-notes/2026)). None runs a test-first tester as a separate role, and no vendor documents routing models by data class at a gateway, although that absence was not checked exhaustively. On shared rooms, incident intake and keeping credentials out of the sandbox the factory is at rough parity: Amp ships multiplayer control of a cloud sandbox ([Amp](https://ampcode.com/news)), Devin Oncall triages PagerDuty incidents, and Claude Code attaches GitHub credentials through a proxy outside the VM ([Claude Code](https://code.claude.com/docs/en/claude-code-on-the-web)). Since the v3 sessions the factory has also closed two gaps that earlier research named: one maintainer approval of the current head now *is* the merge (`approveToMerge`, proven live on aws-0 on 2026-10-30/31), and run cost is broken down by role ([aws-0 results](https://github.com/Smana/ai-native-ref/blob/main/docs/runbooks/agent-factory/results-aws-0-2026-10-30.md); [status record](https://github.com/Smana/ai-native-ref/blob/main/docs/runbooks/agent-factory/results-status-record-2026-10-31.md)).

The ranking in section 2 weighs three things in order: whether adopters at scale name the gap with measured data, how many of the four lenses show it, and whether any effect was measured rather than announced. Product launches rank below measured demand, because a launch shows what a vendor bet on, not what worked. Evidence quality is uneven across lenses. Hosted and review-product numbers are vendor-reported [V]. Adopters publish volumes rather than rates: Spotify merges **1,000 agent PRs every 10 days**, Stripe opens **more than 1,300 PRs a week** with no human-written code, and Ramp attributes **75% of merged PRs** to its Inspect platform ([InfoQ](https://infoq.com/news/2026/03/spotify-honk-rewrite); [InfoQ](https://infoq.com/news/2026/03/stripe-autonomous-coding-agents/); [Pragmatic Engineer](https://newsletter.pragmaticengineer.com/p/why-ramp-built-inspect)). And merge rates disagree by definition: **71.48%** for agent PRs on public GitHub ([AIDev](https://www.alphaxiv.org/overview/2601.15195)) against **32.7% merged within 30 days** in enterprise telemetry ([LinearB](https://linearb.io/library/ai-in-software-development)). Any merge-rate claim needs its denominator and its review condition stated.

## 3. Verification and review capacity carry the only measured demand

**Pre-PR verification on real services (rank 1) has the broadest support of any gap.** On public GitHub the CI outcome predicts an agent PR's fate better than reviewer interaction: each additional failed check cuts merge odds by about 15%, and CI or test failures account for 17% of rejections ([AIDev](https://www.alphaxiv.org/overview/2601.15195)). Adopters at scale built verification before anything else. Spotify runs a separate verification service that abstracts CI, after its agents took shortcuts such as "commenting out failing tests or downgrading Java versions" ([InfoQ](https://infoq.com/news/2026/03/spotify-honk-rewrite)); Ramp found third-party harnesses "couldn't verify changes end to end" without its internal telemetry and feature flags ([Pragmatic Engineer](https://newsletter.pragmaticengineer.com/p/why-ramp-built-inspect)); Stripe runs CI, tests and static analysis before any human review ([InfoQ](https://infoq.com/news/2026/03/stripe-autonomous-coding-agents/)). Hosted products converged on the agent running its own work: Cursor's agents run the software they built and attach videos, screenshots and logs to the PR ([Cursor](https://cursor.com/changelog/02-24-26)), Devin records test runs and offers live previews ([Devin](https://docs.devin.ai/release-notes/2026)), and Copilot runs CodeQL, an advisory-database check on new dependencies and secret scanning before it finishes [2025] ([GitHub](https://github.blog/changelog/2025-10-28-copilot-coding-agent-now-automatically-validates-code-security-and-quality/)). The governance lens adds a sobering ratio: 74% of 700 leaders trust their evals to catch a bad release, but only 19% have a gate that blocks every release automatically [V] ([Harness](https://www.harness.io/resources/state-of-agent-dlc-2026)).

For a platform whose host repositories are mostly Flux, Helm and shell, "real services" cannot mean screenshots. Inference: it means rendering and server-side applying a change against a live or ephemeral cluster, running the security scans inside the sandbox, and reading CI logs. Today repositories declare their checks through `agent-checks`, but the Trivy, Checkov and TruffleHog-verification scans run in CI only ([sandbox-checks design](https://github.com/Smana/ai-native-ref/blob/main/docs/superpowers/specs/2026-10-22-sandbox-checks-design.md)), and the judge's quote of a failing CI log stays empty "unless the harness's egress allows GitHub's Actions log host", which the status page leaves to the platform owner's security decision ([status](https://github.com/Smana/ai-native-ref/blob/main/website/content/docs/status.md)). Visual evidence also carries a privacy cost: agent-created screenshots exposed more than 13,000 internal images from over 300 organisations in September 2026 ([The Hacker News](https://thehackernews.com/2026/09/ai-coding-agents-exposed-13000-internal.html)). The factory's public/internal data-class split already draws that boundary.

**A review inbox with routing (rank 2) rests on the strongest quantified demand.** Across 8.1M PRs from 4,800 teams, agentic PRs wait a P75 of **17.6 h for pickup against 3.4 h**, run **89 lines at the median against 26**, and merge within 30 days **32.7% of the time against 84.4%** ([LinearB](https://linearb.io/library/ai-in-software-development)). Spotify answered "review volume grew faster than review capacity" with a PR inbox, auto-merge for documentation, self-approval by migration owners and the closing of stale PRs ([InfoQ](https://infoq.com/news/2026/03/spotify-honk-rewrite)); Uber routes agent PRs through a "Code Inbox" ([Uber](https://background-agents.com/summit/sessions/nikhil-ramakrishnan/)). The fastest published gain came from a cheaper human decision: at Ona, with a bot approving low-risk PRs and a human still clicking merge, median time to first approval fell from 2 h 49 min to 3.8 min ([Ona](https://ona.com/stories/auto-approving-low-risk-prs)), while Assembled watched first-review waits rise from 3.5 h to over 16 h as agent volume grew ([Assembled](https://www.assembled.com/blog/code-review-bottlenecks-how-we-hill-climbed-our-way-to-higher-pr-throughput)). The factory has taken the first step: one approval merges, its room list counts the rooms that need you ([status record](https://github.com/Smana/ai-native-ref/blob/main/docs/runbooks/agent-factory/results-status-record-2026-10-31.md)), and it records human wait by reason and class ([auto-merge safety](https://github.com/Smana/ai-native-ref/blob/main/website/content/docs/operate/auto-merge-safety.md)). What it lacks is the inbox: one prioritised queue across repositories, routing to the right reviewer, and a rule for work nobody will review.

**The PR continuation loop (rank 4) is the industry norm, not a bet.** Six hosted products and Bugbot ship it: Claude Code's auto-fix, Copilot's Agent Merge, Cursor's PR subscriptions, Devin waking on comments, Jules's CI Fixer and Amp's comment follow-ups ([Claude Code](https://code.claude.com/docs/en/claude-code-on-the-web); [GitHub](https://github.blog/changelog/2026-10-28-agent-merge-watches-and-fixes-pull-requests-in-the-cloud/); [Cursor](https://cursor.com/changelog/08-19-26); [Devin](https://docs.devin.ai/release-notes/2026); [Jules](https://jules.google/docs/changelog/); [Amp](https://ampcode.com/news)). The differences are the useful part. Copilot fixes merge conflicts, while Claude Code cannot, because GitHub emits no webhook for them. Claude asks before acting on ambiguous or "architecturally significant" comments; Jules's Reactive Mode acts only on @mentions; Bugbot caps autofix at three attempts per PR ([Bugbot](https://cursor.com/docs/bugbot)); and Devin's "fix-before-post" sends review findings to the running session and posts only what stays unfixed. The factory already fixes red CI on its own PRs and lists the loop as planned "if tasks are abandoned on pull requests that could still be fixed" ([status](https://github.com/Smana/ai-native-ref/blob/main/website/content/docs/status.md)); the field treats that condition as met by default.

**Calibration (rank 13) and reviewer severity with finding resolution (rank 14) ask whether the factory's own judge and reviewer are right, and they are among the cheapest items on the list.** Every review product read has severity tiers and measures how often its findings get fixed, while the factory's reviewer returns a binary `approve` or `changes` and Maku exports no metric on reviewer findings ([Maku operations](https://github.com/Smana/maku/blob/main/docs/operations.md)). Codex "flags only P0 and P1 issues" on GitHub ([OpenAI](https://learn.chatgpt.com/docs/third-party/github)); Qodo grades findings Error, Warning or Recommendation and "may deactivate" a rule "if its findings are rarely fixed" ([Qodo](https://docs.qodo.ai/administration/rule-management)); Bugbot reports a 78% resolution rate [V] ([Cursor](https://cursor.com/changelog/04-08-26)); Greptile v4 raised the share of comments addressed from 30% to 43% in an A/B over hundreds of thousands of PRs, with an LLM deciding "addressed" [V] ([Greptile](https://www.greptile.com/blog/greptile-v4)). In the wild only 0.9-19.2% of valid AI review comments led to a code change [S] ([arXiv 2508.18771](https://arxiv.org/pdf/2508.18771)). Calibration needs no new data: the factory records each PR's outcome (`auto_merged`, `approved_merged`, `human_merged`, `reverted`, `follow_up`), so the agreement of the judge's `met` and the reviewer's `approve` with those outcomes is a join. Langfuse ships exactly that view, "a human-vs-AI agreement view for checking whether an LLM judge matches human labels" ([Langfuse](https://langfuse.com/docs/evaluation/overview)). The need is real: benchmark-trained critics scored an AUC of 0.45-0.48 on production outcomes in OpenHands' own study ([OpenHands critic paper](https://arxiv.org/html/2603.03800)), LLMs prefer text they recognise as their own ([Panickssery et al.](https://arxiv.org/abs/2404.13076)), and Spotify dropped its LLM judge as "too rigid" ([InfoQ](https://infoq.com/news/2026/03/spotify-honk-rewrite)). Inference: learned review rules need PR volume the factory lacks, so the form that fits is CodeRabbit's or Qodo's "propose, then a human activates" ([CodeRabbit](https://docs.coderabbit.ai/knowledge-base/learnings)), which in GitOps is a PR to the steering notes.

**A plan approval gate (rank 15) has product convergence but no adopter demand.** Copilot (2026-04-01), Devin's Interactive Planning [2025] and Claude's plan mode let a human approve a plan before code ([GitHub](https://github.blog/changelog/2026-04-01-research-plan-and-code-with-copilot-cloud-agent/); [Cognition](https://cognition.com/blog/devin-2); [Claude Code](https://code.claude.com/docs/en/claude-code-on-the-web)); Coder's "Plan first" mode confines the agent to a plans directory until the user clicks "Implement plan" ([Coder](https://coder.com/docs/ai-coder/agents)); gh-aw gates runs through GitHub environment approvals and kagent through per-tool `requireApproval` ([gh-aw](https://github.com/github/gh-aw/blob/main/docs/src/content/docs/reference/triggers.md); [kagent](https://kagent.dev/docs/kagent/concepts/agents)). The only effect size is Jules's Planning Critic, a second agent that reviews plans which skip human approval, credited with a "9.5% reduction in task failure rates" [V] ([Jules](https://jules.google/docs/changelog/)). The counter-evidence is over-specification: Kiro produced "a total of 16 acceptance criteria" for a small bug ([Böckeler](https://www.martinfowler.com/articles/exploring-gen-ai/sdd-3-tools.html)). The factory's scoper already writes acceptance checks or asks one question; what it lacks is a human wait on classes where a wrong plan is expensive, which is why a per-class switch fits the evidence better than a universal gate.

## 4. Platforms went proactive, fleet-wide and stateful in 2026

**Fleet campaigns (rank 3) are where the largest adopters put their volume.** Spotify's scripted Fleet Management cut migrations from nearly a year to under a week for 70% of the fleet, and its agents now target the remaining 30% at a pace of 1,000 merged PRs every 10 days ([InfoQ](https://infoq.com/news/2026/03/spotify-honk-rewrite)); Uber runs migrations through its Shepard tool as a "managed primitive" ([Uber](https://background-agents.com/summit/sessions/nikhil-ramakrishnan/)); Airbnb migrated about 3,500 test files in six weeks against an estimated 1.5 years by hand [2025] ([InfoQ](https://www.infoq.com/news/2025/03/airbnb-llm-test-migration/)). Ona Automations (GA 2026-02-19) is the product form: target repositories by query, one action per repository, concurrency and total caps of 10 and 50 on Core and 25 and 1,000 on Enterprise, a recommended staged rollout, and a per-run report ([Ona](https://ona.com/stories/ona-automations-proactive-background-agents); [Ona lab](https://ona.com/docs/workshops/lab-5-automations.md)). gh-aw's MultiRepoOps runs workflows from a side repository with cross-repository safe outputs ([gh-aw](https://github.com/github/gh-aw/blob/main/docs/src/content/docs/patterns/multi-repo-ops.md)). Inference: the factory's per-class caps and breaker map naturally onto a campaign's staged rollout, and the task categories that merge most often on public GitHub, documentation at 84%, CI at 79% and build at 74% ([AIDev](https://www.alphaxiv.org/overview/2601.15195)), are campaign-shaped.

**Multi-repo tasks (rank 11) are a different shape**: one change that spans several repositories, with a PR in each. Kiro handles it as "a unified task" [2025] ([Kiro](https://kiro.dev/blog/introducing-kiro-autonomous-agent/)), Cursor allows up to 300 repositories per environment ([Cursor](https://cursor.com/changelog/cloud-agent-canvases-and-environments)), and Amp, Claude and Augment support multi-repo projects ([Amp](https://ampcode.com/news); [Claude Code](https://code.claude.com/docs/en/routines)). Copilot's cloud agent stays "sandboxed to a single repository", and its users ask how to work across polyrepos ([GitHub community](https://github.com/orgs/community/discussions/190627)). For the factory the obvious case is a change that spans ai-native-ref and its host.

**Event triggers and schedules (rank 5) are the widest product convergence in the study.** Six of ten hosted products ship scheduled or event-triggered agents, Claude Code and Augment ship preview or partial forms, and five open-source or self-hostable platforms do the same: gh-aw, OpenHands, Ona, Goose and Letta Code. The mechanism is identical everywhere: a saved prompt, repositories, connectors and an environment, plus a trigger (cron, webhook or API, a VCS event, a chat event). Two details are worth copying. gh-aw's `cooldown` skips a run until a duration has passed, `stop-after` disables a trigger after a deadline "to control costs", and one-shot `label_command` and `slash_command` triggers work on any PR alongside a `workflow_run` hook for CI completion ([gh-aw](https://github.com/github/gh-aw/blob/main/docs/src/content/docs/reference/triggers.md)). Devin's **preflight script** runs after the trigger and can validate, enrich or skip the run before any agent budget is spent, and its `llm_check` filters trigger payloads ([Devin](https://docs.devin.ai/release-notes/2026)). Those filters matter because event payloads are untrusted input: in June 2026 "agentjacking" used crafted Sentry error events that coding agents treated as fix steps ([The Hacker News](https://thehackernews.com/2026/06/agentjacking-attack-tricks-ai-coding.html)), which bears directly on RunLore's alert-to-investigation path. Demand is qualitative but consistent: Spotify, Stripe and Ramp all start agent work from Slack threads, tickets and APIs. The factory takes labelled issues, Slack, its CLI and MCP, coding-agent handoffs and RunLore alerts, and plans a webhook API; it has no cron intake, no slash or label command on arbitrary PRs, and no CI-completion or security-alert trigger.

**Memory across tasks (rank 10) carries the study's only controlled result and its sharpest counter-evidence.** GitHub's internal evaluation found Copilot agent PRs merged **90% of the time with memory against 83% without**, a statistically significant gap [V] ([GitHub](https://github.blog/ai-and-ml/github-copilot/building-an-agentic-memory-system-for-github-copilot/)). Six hosted products ship some form of memory, and gh-aw, kagent and Letta Code ship it in open source. Against that, context files gave "no measurable gain" at about 20% more cost in one study [S] ([Gloaguen et al.](https://arxiv.org/pdf/2602.11988)), OpenHands keeps curated skills with a human-reviewed improvement loop rather than learned memory ([OpenHands](https://docs.openhands.dev/overview/skills/monitoring.md)), no open-source project publishes an outcome measurement, and OWASP lists memory and context poisoning as ASI06 in its 2026 agentic top ten ([OWASP](https://genai.owasp.org/resource/owasp-top-10-for-agentic-applications-for-2026/)). The mechanism decides which side applies. Copilot checks each memory against the current code before using it; Bugbot turns review outcomes into rules users can see and edit ([Bugbot](https://cursor.com/docs/bugbot)); gh-aw's `repo-memory` is a git branch with unlimited retention, committed after each run ([gh-aw](https://github.com/github/gh-aw/blob/main/docs/src/content/docs/reference/repo-memory.md)). Inference: memory kept as reviewed code in the repository, a branch or a PR that a maintainer merges, avoids the hidden state drift the original "not planned" decision guarded against, and turns the poisoning risk into a reviewable diff.

**Repository-declared environments (rank 9) are the broadest convergence among the band-2 gaps.** Nine of ten hosted products let each repository declare its toolchain once and reuse a cached image or snapshot: Copilot's `copilot-setup-steps.yml`, Codex's setup and maintenance scripts with containers cached for up to 12 hours, Devin's git-backed blueprints, Cursor's Environments API and Claude's cached setup scripts ([GitHub docs](https://docs.github.com/de/copilot/how-tos/copilot-on-github/customize-copilot/customize-cloud-agent/customize-the-agent-environment); [OpenAI](https://learn.chatgpt.com/docs/environments/cloud-environment); [Devin](https://docs.devin.ai/release-notes/2026); [Cursor](https://cursor.com/changelog/cloud-agent-canvases-and-environments); [Claude Code](https://code.claude.com/docs/en/claude-code-on-the-web)). Adopters rank environment parity just behind review: scaling to hundreds of repositories exposed "missing credentials and Docker requirements" at Spotify, and Ramp's first version failed because local setup was too complex ([InfoQ](https://infoq.com/news/2026/03/spotify-honk-rewrite); [Pragmatic Engineer](https://newsletter.pragmaticengineer.com/p/why-ramp-built-inspect)). The planned warm pool (rank 26) is a different thing, generic pre-started pods; OpenHands' deferred init, which boots pods dormant and pushes credentials and a workspace in by API to keep "per-user data out of the image", shows how the two could combine ([OpenHands](https://docs.openhands.dev/sdk/guides/agent-server/deferred-init.md)), and agent-sandbox v1.0.7 now holds Kueue-gated warm members like unschedulable ones ([agent-sandbox](https://github.com/kubernetes-sigs/agent-sandbox/releases/tag/v1.0.7)).

The remaining product-led gaps concern where work starts and how it is packaged. **Reusable playbooks (rank 12)** mix deterministic steps with prompts: Stripe's "blueprints" do exactly that ([InfoQ](https://infoq.com/news/2026/03/stripe-autonomous-coding-agents/)), Goose recipes take parameters and run subrecipes in parallel ([Goose](https://block.github.io/goose/docs/guides/recipes/recipe-reference)), and Devin converted Playbooks into Skills on 2026-10-23 ([Devin](https://docs.devin.ai/release-notes/2026)); the factory has fixed classes and a steering note per class. **Approving and steering from Slack or mobile (rank 16)** ships at Devin (Slack buttons, previews in threads), Cursor, Claude, Amp and GitHub's Agent HQ [2025] ([Devin](https://docs.devin.ai/release-notes/2026); [Cursor](https://cursor.com/changelog/08-19-26); [Amp](https://ampcode.com/news)), while the factory's status page keeps approval "in the rooms web UI" ([status](https://github.com/Smana/ai-native-ref/blob/main/website/content/docs/status.md)). **Cloud-to-local handoff (rank 17)** lets a developer pull a cloud session into a terminal with its branch and conversation, through Claude's `--teleport` or Augment's `/cosmos` ([Claude Code](https://code.claude.com/docs/en/claude-code-on-the-web); [Augment](https://www.augmentcode.com/changelog/auggie-cli-0-27-0-release-notes)); the factory hands off only in the other direction. **Jira and Linear intake (rank 18)** is planned "when a tracker is in use"; Devin shipped a native Jira agent on 2026-09-30 ([Devin](https://docs.devin.ai/release-notes/2026)).

## 5. Security and measurement: test and read what already exists

### Adversarial drills, not more filters, close the security gap

The factory's substrate controls already exceed most of the field: gVisor, a ServiceAccount and Cilium FQDN egress per run, short-lived GitHub tokens from octo-sts, gateway allow-lists per role and data class, signed images with an SBOM and SLSA provenance, and a written threat model ([Maku security](https://github.com/Smana/maku/blob/main/docs/security.md)). That threat model also names its residuals: sanitising untrusted text is "a filter, not a boundary", and an injected reviewer can approve bad code inside the room. No hard regulatory obligation applies to a self-hosted coding agent today: NIST's agent work is still at concept-paper stage [S] ([NIST](https://www.nist.gov/news-events/news/2026/02/new-concept-paper-identity-and-authority-software-agents)), and the EU AI Act's high-risk duties were deferred to 2027-2028 [S] ([Gibson Dunn](https://www.gibsondunn.com/eu-ai-act-omnibus-agreement-postponed-high-risk-deadlines-and-other-key-changes/)).

**Injection red-team drills (rank 7) are where the research evidence is hardest.** Researchers from OpenAI, Anthropic and Google DeepMind bypassed 12 published prompt-injection defences with adaptive attacks at success rates "above 90% for most", where most had reported near zero, and human red-teamers reached 100% ([Willison](https://simonwillison.net/2025/Nov/2/new-prompt-injection-papers/)). OWASP published its GenAI Red Teaming Manual v1.0 on 2026-10-20 ([OWASP](https://genai.owasp.org/announcement/owasp-genai-security-project-unveils-2026-top-10-for-llm-applications-new-agent-control-standard-and-sponsors-as-community-tops-30000-members/)), and the joint guidance of CISA, NSA and their Five Eyes partners of 2026-05-01 asks for "regular security assessments" of agent deployments ([CISA](https://www.cisa.gov/resources-tools/resources/careful-adoption-agentic-ai-services)). Incidents follow the same shape: PromptPwnd put untrusted issue titles and PR bodies into the prompts of CI agents holding write tokens [S] ([eSecurity Planet](https://www.esecurityplanet.com/de/threats/ai-agents-create-critical-supply-chain-risk-in-github-actions/)), and 87% of 700 leaders report an agent-related security event this year, for agents in general [V] ([Harness](https://www.harness.io/resources/state-of-agent-dlc-2026)). The research for this report met a live sample: Jules's official changelog page embeds an "export prompt" that tells an agent to read the macOS Keychain and local credential files ([Jules](https://jules.google/docs/changelog/)). The fetch tool flagged it and nothing ran; whatever its intent, it is the exact payload a drill would plant. The factory already runs merge drills and keeps a room log to score from, and ai-native-ref runs a nightly Promptfoo job, but against the LLM Semantic Router rather than the factory's agents ([Promptfoo cron](https://github.com/Smana/ai-native-ref/blob/main/tooling/base/promptfoo/cronjob.yaml)). A drill that plants injections in issue text, PR comments, repository files, tool outputs and MCP descriptions, and scores whether any write, egress or approval follows, tests the residual the threat model admits.

**Hardening beyond validated outputs (rank 8) has gh-aw as its reference.** gh-aw's agent job holds no write permission and requests actions as typed safe outputs, each with a per-run `max` ([gh-aw](https://github.com/github/gh-aw/blob/main/docs/src/content/docs/reference/safe-outputs.md)), which is the shape of the factory's planned "agent that writes only through validated outputs" ([status](https://github.com/Smana/ai-native-ref/blob/main/website/content/docs/status.md)). It then adds four layers the factory's plan does not name: a threat-detection job that scans buffered outputs and patches "for secret leaks and malicious changes" before anything is applied, warn mode first; a protected-files rule that blocks agent edits to dependency manifests, CI workflows and agent instruction files such as `AGENTS.md`; integrity filtering that withholds content by author association and merge status; and a staged mode that previews outputs without writing them ([threat detection](https://github.com/github/gh-aw/blob/main/docs/src/content/docs/reference/threat-detection.md); [integrity](https://github.com/github/gh-aw/blob/main/docs/src/content/docs/reference/integrity.md); [staged mode](https://github.com/github/gh-aw/blob/main/docs/src/content/docs/reference/staged-mode.md)). Goose adds an independent reviewer that sees each tool call before it runs, though it fails open ([Goose](https://github.com/aaif-goose/goose/blob/main/documentation/docs/guides/security/adversary-mode.md)). The design literature explains why these layers stack rather than overlap: Meta's "Rule of Two" says one session should hold at most two of untrusted input, sensitive access and the power to change state ([Willison](https://simonwillison.net/2025/Nov/2/new-prompt-injection-papers/)), and CaMeL solves 77% of AgentDojo tasks "with provable security" against 84% undefended ([CaMeL](https://arxiv.org/abs/2503.18813)).

**Signed provenance (rank 19) closes a residual the threat model states plainly**: the merge gate binds pushes to the agents App, "not the task: any implementer run can push as the bot", and commits are not signed ([Maku security](https://github.com/Smana/maku/blob/main/docs/security.md)). Copilot's agent commits are signed and show as Verified, and since 2026-03-20 each carries an `Agent-Logs-Url` trailer linking to its session [S] ([GitHub](https://github.blog/changelog/2026-03-20-trace-any-copilot-coding-agent-commit-to-its-session-logs)). SLSA v1.2 asks at Source level 2 for a provenance attestation per revision recording "who made them" ([SLSA](https://slsa.dev/spec/v1.2/source-requirements)). gitsign signs keylessly from an OIDC token, but GitHub did not show those signatures as Verified at last report [S][U] ([Chainguard](https://www.chainguard.dev/unchained/keyless-git-commit-signing-with-gitsign-and-github-actions)), so commits created through the GitHub API, or a separate attestation, are the practical routes. Inference: SLSA lets a "trusted robot" skip two-party review in a defined context, and the factory's per-class fences are a ready-made definition of that context.

Four smaller security gaps rank lower. A **new-dependency rule (rank 23)** would send PRs that add a package, chart repository, image registry or Action to a human; slopsquatting supports it, but reported hallucinated-package rates disagree about fourfold [S] ([CSA](https://labs.cloudsecurityalliance.org/research/csa-research-note-slopsquatting-ai-supply-chain-20260419/)), and gh-aw's protected files already cover manifests. An **egress denial view (rank 21)** would report blocked requests per run, as gh-aw's `audit`, Coder's Agent Firewall and Copilot's firewall do ([gh-aw](https://github.com/github/gh-aw/blob/main/docs/src/content/docs/reference/network.md); [Coder](https://coder.com/docs/ai-coder/agent-firewall); [GitHub docs](https://docs.github.com/en/copilot/how-tos/copilot-on-github/customize-copilot/customize-cloud-agent/customize-the-agent-firewall)); the factory denies by default but surfaces no denial report ([egress runbook](https://github.com/Smana/ai-native-ref/blob/main/docs/runbooks/agent-factory/03-egress.md)). An **audit export (rank 24)** would stream the append-only room log to an external store with tamper evidence, the direction GitHub's agent audit events and NIST's call for "auditing and non-repudiation" point [S] ([GitHub](https://github.blog/changelog/2026-02-27-enterprise-ai-controls-agent-control-plane-now-generally-available/); [NIST](https://www.nist.gov/news-events/news/2026/02/new-concept-paper-identity-and-authority-software-agents)); it matters mainly to adopters under audit. MCP tool-description pinning stays unranked while the federated servers are mostly first-party.

### The factory records outcomes it does not yet read

**Outcome analytics per class and model (rank 6) is the only gap all four lenses support, and the factory already holds the data.** Maku exports PR outcomes, time to PR, handoff to merge, human interventions and run cost by tier and role ([Maku operations](https://github.com/Smana/maku/blob/main/docs/operations.md)). What is missing is the joined view: outcome and cost per class and per model, cost per accepted PR, and agent-versus-human instability. gh-aw classifies each output "based on repository state, not on the workflow's self-assessment" and advises: "Do not collapse them into a single score" ([gh-aw outcomes](https://github.com/github/gh-aw/blob/main/docs/src/content/docs/reference/outcomes.md); [measuring impact](https://github.com/github/gh-aw/blob/main/docs/src/content/docs/guides/measuring-impact.md)). DORA now counts five metrics, adding **deployment rework rate** to change fail rate on the instability side ([DORA](https://dora.dev/guides/dora-metrics/)), and its 2025 report found AI adoption still has "a negative relationship with software delivery stability" ([Google Cloud](https://cloud.google.com/blog/products/ai-machine-learning/announcing-the-2025-dora-report)). Hosted vendors report Devin's ACUs per merged PR and Copilot's per-repository PR activity ([Devin](https://docs.devin.ai/release-notes/2026); [GitHub](https://github.blog/changelog/2026-07-17-repository-level-github-copilot-usage-metrics-generally-available/)). Ona treats "a model swap" as a policy change requiring sign-off ([Ona](https://ona.com/stories/auto-approving-low-risk-prs)), which is the argument for a per-model cut. On the demand side, ROI is unresolved: METR called its own follow-up "an unreliable signal" [S] ([Rob Bowley](https://blog.robbowley.net/2026/04/04/metrs-developer-productivity-research-2026-update/)), and Uber's COO reportedly cannot tie AI spend to product outcomes [S] ([Quartz](https://qz.com/uber-coo-ai-spending-harder-justify-052626)). **No adopter publishes a revert rate or a cost per merged PR** for agent work; the factory could.

**A run timeline with run-to-run diff (rank 20) answers a deliberate gap.** The factory's traces carry no content by design, one span per model call through a redaction allow-list ([observability runbook](https://github.com/Smana/ai-native-ref/blob/main/docs/runbooks/agent-factory/08-observability.md)). Langfuse and Braintrust join model calls, tool calls and costs on one view, and gh-aw's `audit` diffs a run's tool and network behaviour against earlier runs ([Langfuse](https://langfuse.com/docs/evaluation/overview); [gh-aw audit](https://github.com/github/gh-aw/blob/main/docs/src/content/docs/reference/audit.md)); OpenTelemetry's GenAI agent spans are still in Development status ([OpenTelemetry](https://opentelemetry.io/docs/specs/semconv/gen-ai/gen-ai-agent-spans)). Inference: the room log, which ADR 0044 already makes "replayable after any disconnect", can carry the timeline without putting content into traces ([ADR 0044](https://github.com/Smana/ai-native-ref/blob/main/website/content/docs/decisions/0044-room-session-protocol.md)), and the same view serves the animated run view proposed in issue #280.

Five measurement and cost items rank lower. A **release-gating regression eval (rank 22)** would run a small golden subset on each Maku release; Langfuse's GitHub Action fails a PR when a score drops ([Langfuse](https://langfuse.com/docs/evaluation/overview)), but the factory's bench waits "if a sponsor funds the bench sessions" ([status](https://github.com/Smana/ai-native-ref/blob/main/website/content/docs/status.md)). **Pre-call budget reservation (rank 25)** is gh-aw's admission gate, where an external authority returns `max_ai_credits` before the agent starts ([gh-aw](https://github.com/github/gh-aw/blob/main/docs/src/content/docs/blog/2026-10-27-activation-gate.md)); Uber exhausted its year's AI coding budget in about four months and then capped spend at $1,500 per person per tool a month [S] ([Silicon UK](https://www.silicon.co.uk/workspace/uber-ai-caps-630085)), but the factory already caps each run, each day and each identity. **Multi-team tenancy (rank 27)** ships only in commercial editions such as OpenHands Enterprise's Keycloak RBAC and org budgets ([OpenHands](https://docs.openhands.dev/openhands/usage/cloud/organizations/budgets.md)), and no adopter source asks for it, plausibly because the public adopters run single-tenant platforms. **SLO-driven auto-revert (rank 28)** has no product precedent for bot merges; it is an inference from SRE practice. **Best-of-N (rank 29)** survives only in Codex's one to four attempts with a manual pick [S] ([Vaughan](https://codex.danielvaughan.com/2026/04/01/codex-cloud-exec-best-of-n-attempts/)); no open-source platform ships it and no vendor launched it in 2026.

## Conclusion

The evidence moves v4 away from adding capability and toward closing the loop around what already exists. Four of the gaps with strong support, outcome analytics, judge and reviewer calibration, finding resolution and the run timeline, are joins and views over records the factory already keeps (outcomes, cost by role, the room log, the decision record). Built, they would let the factory report what no adopter or vendor publishes for agent work: a revert rate and a cost per merged PR, by class and by model. That is the honest answer to the field's unresolved ROI question, and it turns the factory's lead in merge policy into evidence rather than assertion at the moment self-hosting stops setting it apart.

The proactive gaps carry a sequencing implication that no single source states. Event triggers, fleet campaigns, multi-repo tasks and memory each enlarge the untrusted-input surface: alert and webhook payloads (the agentjacking pattern), writes across many repositories, and state that outlives a task (OWASP's ASI06). Adaptive attacks defeat static filters, so injection drills and output-side hardening are worth most if they land before the first unattended trigger rather than after it. In the same way, the adopter record shows that more agent output moves the constraint to review; verification before the PR and an inbox after it are what keep wider autonomy from simply lengthening the queue.
